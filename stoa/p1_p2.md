# P1 (stacking) + P2 (multi-scale fusion) + door filter — 14.11.2026

Spend: **$0** (CubiCasa only + existing Claude caches). Code: `stoa/fusion.py`, `stoa/stack.py`,
door filter in `stoa/cubicasa_count.py` (`doors()`, `P["door_*"]`). New caches: `cache/cubicasa_s1.5`, `cache/cubicasa_s2` for all 241 plans.
Model selection only on `in_test=False` plans (grouped 5-fold CV), score on `in_test` (27 plans, 217 questions).

## Door filter (main finding)
CubiCasa *detects* doors (raw door components ≈ expected on the worst plans: 28 vs 26, 22 vs 24, 17 vs 17), but the
icon area threshold relative to building area dropped 60–90% of them (doors are thin wall openings; big/2-floor plans → big threshold).
New: dilate 3 px to merge fragments, area ≥ 12 px, mean prob ≥ 0.5.

| doors | all plans (n=176) | in_test (n=19) |
|---|---|---|
| old filter | 34.7%, bias −1.97 (train) | 31.6%, bias −4.21 |
| new filter | **44.9%**, bias −0.25 (train) | 31.6%, bias −0.68 |

CubiCasa overall 62.5% → 63.3% (all), other types unchanged.

## P2: multi-scale fusion (x1, x1.5, x2; each 4-rot TTA)
- Union of views removes undercount bias (windows −1.8 → −0.6) but exact match barely moves.
- Per-plan scale (`adapt`: x1.5 if px/m < 30): doors train 31 → 38%, toilets test 69 → 77%.
- Merging collinear fragments hurts (GT often counts **sashes**, not frames: plan 1967 = 12 frames × 2 = 24 expected).
  Annotation is inconsistent across plans (frames vs sashes) → windows ceiling ~30–37% for mask counting.

## Caveats
- in_test has only 19–27 questions per type; ±1 answer = ±4–5 pp.
- The hybrid `verify` route for doors was run with the OLD door filter (fewer candidates). Re-running verify with the
